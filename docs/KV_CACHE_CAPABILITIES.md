# KV cache 关键能力与实施计划

2026-09-09。最初研究基线：`cb75be3`；批次A已推送`d449ad0`、B已推送`0290767`，本轮完成C的读优先增量。本页是KV cache的统一能力计划；[可靠性记录](KV_CACHE_RELIABILITY.md)记录实际实现与验证。下文九项能力是完整目标，是否交付以本页“落地进度”和实际报告为准，不能把整项规划当作已实现。

目标是让本机 agent 在 10k+ 提示词、多轮工具调用、会话分叉和有限内存下，稳定复用推理状态，降低重复 prefill、状态复制和 SSD 读写成本。保持 Swift / MLX 专用 runner、当前模型与量化、先本机 prefill/decode 分离的方向。MTP 性能继续放在后段。

## 一、项目结论

采用 **完整混合状态检查点 + Attention/QSA 分块共享 + RAM/SSD 分层存储 + 调度器联合准入**。前缀树负责查找；检查点证明状态可以恢复；存储层负责字节与生命周期；调度器决定何时恢复、计算和回收。

本模型的恢复对象不是单独的 KV：36 层 GDN recurrent/conv、12 层 Attention KV/QSA 原始与池化索引、PLE conv/n-gram 历史及各层 offset 必须对应同一 token 边界。较深 GDN/PLE 状态不能任意裁成较短状态；在更深处找到部分 Attention 页，也不能把它算成完整命中。

先补可靠性、有效收益指标和完整会话复用，再改物理页与 attention kernel。当前整快照路径继续作为正确性基线。上游算法的名称和存在状态不构成本项目的性能验收。

## 四、九项关键能力

编号用于后续 PR、测试及结果记录。P0 是本机工业候选的必备项；P1 是容量/成本优化阶段，不能拿它们拖延 P0 的交付。

### K01 / P0：完整状态、身份与恢复事务

定义统一的 `PrefixStateManifest` 契约：准确 token 边界、状态组、shape/dtype/layout、全局及层 offset、模型身份、数值配置、格式版本与状态 ABI。名称为规划中的接口，当前不要求先重写全部现有类。

恢复流程为 `查找候选 → 固定引用 → 预留全部目标与临时额度 → 读取/校验 → 执行器导入 → 完成后可用`。任何阶段取消、失败或 clear epoch 改变都不发布部分状态；每份 lease/ticket 只有一个释放 owner。索引移除、会话结束与物理释放分别处理。MLX 惰性复制和 Metal 使用完成之前，引用仍必须有效。

CacheIdentity 延续现有保守的模型/运行配置绑定；为未来共享增加服务端可信隔离域。当前本机单用户域即可；跨用户共享前补身份、配额与清除范围，任意客户端 salt/session ID 不构成授权。保持原有本机大权重 stat 指纹的使用边界；可搬迁缓存或远端 PD 再引入可验证内容身份，不能把路径指纹当跨机证明。

验收：每一事务边界注入取消、迟到/重复完成、清除、缺组和错 offset；有效恢复的完整状态与冷 oracle 一致，排空后请求/临时资源归零，其他消费者继续正确。

### K02 / P0：完整多轮会话、工具结果与分叉复用

HTTP 对**完整渲染后的请求一次分词**，以准确 token 最长公共前缀寻找已存在的完整检查点。覆盖系统/工具定义、历史 user/assistant、tool call/result 和重复文档；会话 ID 仅提供保留偏好，不补全客户端未提交的历史。

第一版仍从 prefill 发布检查点：有限保留系统锚点及靠近完整 prompt 尾部的检查点，分叉只复用真实存在的共同边界。沿用原来的 chunk416 网格、求值及数值配置，最后一个 prompt token 按当前协议重算以获得 logits。不能简单把每个树节点都变成检查点，也不能为对齐消息边界悄悄拆分原有计算块。

每路径检查点数与字节均有限额；近期会话是可淘汰的软保护。较长状态不能自动删除一个仍有分叉价值的较短 recurrent 检查点。decode 产生的状态是否能替代 canonical prefill 检查点是单独数值问题，首版不使用该捷径。

查找上限、拟发布的检查点集合与 single-flight 生产者键必须分开。当前 flight 按整个目标前缀建键；仅扩大 `prefixCacheMaxTokens` 会让不同 user/tool 尾部丢失共同系统前缀的冷请求合并。应按共同完整检查点身份协调生产，之后各分支独立推进，不能把整个请求串行绑定给另一个分支。

验收：真实 10k+ agent 多轮工具闭环、相同会话两分支、编辑较早消息、工具定义改变、BPE 边界变化；特别覆盖冷启动时共同长系统前缀、不同尾部同时到达。命中范围扩展到历史消息后仍输出/状态一致；报告少算多少 token、减少多少 TTFT、增加多少检查点字节，而不只报告 hit 次数。

### K03 / P0：统一内存压力、准入与公平容量

保留现有逻辑账本，并分别观测 MLX active/cache/peak、进程 footprint/RSS、系统 memory pressure。新页共享实现按唯一物理分配计总额，同时记录各域逻辑占用；不得把多方引用重复相加，也不得遗漏暂存和写中副本。权重、activation、allocator 保留不属于现有状态账本，必须留实际运行余量。

增加正常/警告/临界水位与恢复滞回：先停止可选预取/写回和缓存提升、淘汰无活动引用的状态，再减少新 prefill admission；保留活跃 decode 的续写及暂存空间。容量仍不足时有界等待或明确拒绝；不能期待系统 swap 替我们管理状态。恢复到安全水位后自动恢复 admission。

按会话/服务端域设置有界软份额，避免一次长文档挤掉全部热前缀；所有硬上限始终生效。多等待者不能对同一笔“即将淘汰”的容量重复预支。

验收：真实系统压力加多前缀 churn、SSD 导入/写回交错。逻辑限额不越界，活跃状态不被回收，拒绝后服务恢复；同时验证进程实际占用与压力曲线，不能用人为填满账本代替。

### K04 / P0：有界、可退出等待的 SSD 恢复与写回

保留现有原子文件、checksum、进程锁、恢复和 TTL/LRU。增加缓存目录所在卷的最小可用空间水位，计入临时文件与并发预留；外部进程仍可能消耗空间，因此实际 ENOSPC 也须正确回退。

队列区分前台恢复、可选预取、后台写回；前台恢复优先于尚未开始的后台任务，但共享 SSD 上 PLE n-gram 读取及 decode 延迟必须有护栏。所有任务先预留 job/bytes/staging，采用有界传输块及写入速率控制，避免大归档长期堵住后续恢复。

每次恢复有请求等待期限：预计排队+读取+校验+导入慢于重算，或超期时，可取消等待并回到更短的完整前缀/冷算。**退出等待不等于正在执行的 POSIX I/O 已终止**；底层完成前继续持有缓冲和额度，迟到结果不能重新附着已结束请求。挂起 I/O 不能导致无限增建 worker、重复读取或过早释放；预算不足时也不能无条件启动冷重算。

写回是可跳过的工作：热度准入、队列水位、临时空间及剩余 SSD 空间不允许时正常推理。请求返回不等待可选写回。关闭先停止新 admission，取消未开始任务并在 graceful deadline 内排空；超期明确报告未排空，仍运行的 I/O 保留 owner/预算，不能强制释放其缓冲区或宣称关闭完成。若进程必须退出，由操作系统回收进程资源，下一次启动走归档恢复；库接口不能保证挂起的系统调用立即结束。

验收：慢盘、满盘、删除失败、取消后迟到完成、写中退出、重启清理、与 PLE 读取竞争。记录有效恢复与浪费读取、实际写入字节和 prefill/decode 尾延迟。

### K05 / P0：缓存感知的本机 PD 调度与交接

把“可运行 prefill / 可运行 decode / 等待前缀生产者 / 等待 SSD”分别建模。等待者不占 GPU 可运行槽，但其真实状态/未来准入预留继续计费。保留已有 single-flight 和 leader 取消接管；不让同前缀等待堵住其他 decode。

缓存成本参与 admission 和顺序选择，等待时间 aging 保障冷长请求能够推进；先保持已有 decodeBurst 默认。prefill 的 TTFT/实算吞吐与 decode 的 TPOT/吞吐独立考核。

现有单次 handoff 逐步统一到 K01 的 manifest/ownership 契约。前缀缓存描述一个 prompt 的可复用状态；**可暂停请求的执行快照**还需保存阶段、当前位置、待发布 token、已发输出/工具解析状态及恢复所需元数据，不能直接把前缀 archive 当成完整执行快照。请求暂停卸载/恢复为后续扩展，远端 PD transport 再后置。

验收：冷 prefill、热命中、慢 SSD 恢复与长 decode 混合；先设明确排队期限与公平规则，再检查无饥饿、无双重消费、取消清理及两阶段延迟。跨进程部署不阻塞本机完成。

### K06 / P0：可运维、可核算的收益与工业验收

在现有 health/生成报告上补齐统一字段，而非另建一套不可对账的指标。请求级固定：

`prompt_tokens = computed_prompt_tokens + ram_restored_tokens + ssd_restored_tokens`。

来源只记录**最终有效前缀中实际采用**的 token。SSD 读入后提升 RAM 不能重复计；查找失败、丢弃预取、回退重算均不算有效命中。`computed_prompt_tokens` 是最终采用状态中本请求计算的唯一 prompt token，参与上述守恒；另设 `actual_prefill_work_tokens` 记录重试、回放和丢弃计算在内的所有实际工作，`recomputed_tokens` 记录额外重算。实际工作可以超过 prompt 长度，不能塞入同一恒等式。该恒等式针对完成 prefill 的请求，取消前的部分工作单列。执行吞吐用 actual work，业务少算量用最终来源，两者分别报告；TTFT 包含排队、等待、恢复和计算。

补充有效 token 复用率、查找/导入成功率、wait/read/import/save 分位数、净收益估计、放弃原因、copy bytes、硬引用/软保留字节、淘汰后回读、物理文件/逻辑 payload 与临时字节。净节省时间用匹配负载的冷基线或成本模型估计，不能把缓存命中直接换算成实测节省。没有设备物理 I/O/DRAM 计数时留空，不拿应用层 read/write 字节冒充介质或 DRAM 流量。

运维接口提供有界统计、清除范围、暂停 SSD admission、排空状态与故障原因；不得把 prompt/token key 原文写入普通指标，标签数量也需有限。缓存故障可退算；设备故障仍明确标记不可用。

### K07 / P1：真正的 Attention/QSA 页共享与 COW

建立不可变完整页、每请求逻辑页表、私有可写尾页和引用/fence。GDN/PLE 在准确边界保存完整 recurrent 检查点，并在续写时私有化；QSA raw/pooled 索引按自身布局对齐，不能因当前 sparse selection 未选中就永久丢弃历史。

**物理页大小、前缀匹配单位、recurrent 检查点间距、prefill chunk416 是四个不同参数。** 页大小由本模型布局和 Metal 实测决定，不照搬 CUDA 的常数。早期不改变 prefill 数值边界。

从直接追加和读取页表的 attention/QSA 路径验证，再接整模型。每步若仍重新拼成完整连续 KV，则只完成主机管理，不能宣称分页性能能力已交付。完整页分支共享；尾页被多个 owner 引用才 COW；设备完成前不得复用页。

验收：页边界/尾页/两分支/一支取消/clear 与复制交错；准确状态和完整输出回归；长上下文实际复制字节、唯一驻留字节、TTFT/TPOT 改善。存储搬移必须保留原始位。kernel 归约变化另立数值和性能验收，不能以允许近似掩盖缓存错误。

### K08 / P1：增量分块持久化与受控回收

K07 稳定布局后，SSD 从整份 archive 逐步升级为共享页/状态块加 manifest；允许跨检查点复用 Attention/QSA 不变块，新增 recurrent 检查点独立存储。块身份包括布局、状态组及前缀上下文，单独 checksum；manifest 只有全部依赖耐久后才能原子发布。

区分 logical manifest、物理块、在途读者及未提交发布事务的引用。writer 从写入到 manifest commit/abort 始终固定相关块；GC 不能把已写但尚未提交的块当孤儿。删除会话/manifest 不得删除仍被其他前缀、发布事务或恢复任务引用的块；跨崩溃恢复能重建依赖并有界回收孤儿，计入临时/孤儿字节。迁移格式需版本隔离，旧格式安全 miss 或走明确只读兼容，不能静默错读。

验收：共享两条长前缀的增量保存降低重复写入/空间；任意块缺失或损坏只拒绝受影响的完整状态；GC 与发布/删除/重启交错不误回收。主要观察写放大、恢复开销及 PLE/decode 影响，去重率单独不构成收益。

### K09 / P1：按复用价值选择检查点与淘汰

LRU 继续作为可用基准。先用真实多轮 trace 做 shadow 计分，比较热度衰减、二次命中准入、系统锚点与会话继续点软保护。成本模型考虑近期复用概率、节省的 prefill、保存/恢复成本和保留字节；避免扫描型一次性长文档污染缓存。

RAM 命中、SSD 命中和冷算的选择包含排队与导入成本。保存更多 GDN/PLE 检查点会重复固定状态，必须约束路径密度；较长检查点无法裁剪时，旧锚点不能仅因被覆盖就删除。策略参数依据本机采样，不复制其他模型常量。

验收：相同请求 trace、同容量下与 LRU 对照，分别报告 TTFT、TPOT、节省的计算、保存/恢复与写放大，且冷请求无饥饿。收益未成立保持 LRU；策略可关闭。

## 五、实施批次与交付约束

| 批次 | 工作与依赖 | 可以合入主线的结果 |
| --- | --- | --- |
| A，立即 | K01/K03/K04/K06：补最小可用空间与故障恢复、真实压力 admission、读等待完成契约及 token/成本指标；现有整快照保持 | 每项独立补齐故障回归和真实行为记录；先交付安全与可测量的管理能力，不等待新页池 |
| B，紧接 A；分词/策略开发可并行 | K02 + K05 的会话复用与调度；只使用已存在/原网格新发布的完整 checkpoint | HTTP 多轮/工具/分支自动复用，有限路径保留，实际少算 token；与 A 一起完成 P0 服务验收 |
| C，独立性能候选 | K07，依赖 A/B 的身份、所有权和基准负载；先页访问小路径再整模型 | 真正页表读取、追加与 COW；同时通过状态正确性、容量和分阶段性能检查后启用 |
| D，容量成本优化 | K08 依赖 C；K09 的 trace/shadow 可提前开始，正式策略依赖可靠成本数据 | SSD 增量保存/恢复、引用回收与可关闭的价值策略；有实际收益才改默认 |
| E，核心缓存成熟后 | 活跃请求执行快照、暂停 offload/resume，再考虑远端 PD、KV 压缩及最终 MTP 配合 | 分别建立新的故障/数值/性能验收，不以“前缀恢复成功”替代执行快照完成 |

本轮结束后的第一批代码应从 A 开始；B 的完整会话复用紧随其后，不能只做观测而长期不交付使用收益。K01/K06 贯穿所有批次，不先做通用框架重构。每个完成的有效增量连同文档/测试及时 commit、推送当前主线；实验未获收益保留显式开关或结束候选，不长期堆积悬空分支。

## 六、什么条件才称为本机工业可用

这里定义的是**本项目拟采用的发布门槛**，不是宣称存在统一行业认证。发布配置先限定当前模型、AR、16k 上下文、loopback API 与明确并发/容量上限。跨机器、多租户公网、MTP 缓存均不包含在该范围。

| 维度 | 验收要求 |
| --- | --- |
| 状态正确性 | 冷/RAM/SSD、短/10k+、多轮工具、分叉、编辑历史的完整输出与混合状态对照；覆盖 416 网格、QSA 结构边界及上下文/输出预算末端。对存储复制要求位保持；缺组/错身份/损坏不得恢复 |
| 所有权与故障 | 每个传输/导入/发布/clear 边界取消及迟到完成；写中进程退出、满盘、删除失败、重启恢复；无双释放、无活动页提前复用，排空时 request/workspace/transfer 归零，缓存保留字节可解释 |
| 实际容量 | 逻辑上限、临时文件与唯一物理页分别对账；真实 macOS 压力触发 admission 降级并恢复，不能用假 lease 占满代替。数据/元数据/指标均有界 |
| 持续运行 | 候选先做 2 小时，发布配置做 24 小时混合负载；工作集达到缓存容量的 2–4 倍，明确包含持续 SSD 恢复、不同前缀淘汰、会话分叉和取消。分设定期排空查泄漏与不人为排空的持续负载窗口；后者检查在途积累与长期公平，不能全靠周期 drain。预热后的分时段资源分布和趋势可解释，无越界、崩溃或持续未回收增长。提前结束只报告实际完成范围 |
| 性能与公平 | 同版本固定 trace，分别覆盖 cache disabled/cold/RAM/SSD/churn；分别报告 TTFT、TPOT、实算 prefill 吞吐与有效 decode 吞吐。默认候选以冷路径及 decode p95 不劣于基线 5% 为初始护栏，超过需定位并重新选择；热复用需获得实际 TTFT 收益。漂移不清则结果未定，不能算通过 |
| SLO 与可诊断性 | 在发布配置验收前固定各负载的 TTFT/TPOT 目标、排队/恢复期限和最大并发，随发布报告保存；观测到的分位数不自动变成承诺。超限有明确错误/回退、原因及恢复记录，冷请求在定义的等待规则内取得进展 |

所有性能对照仍串行使用受控模型资源，保留失败和漂移窗口；不改变用户供电设置，不把适配器规格当成性能结论。无需为每个小改动重跑全部长稳；涉及生命周期、存储格式或页管理的发布候选必须完成对应增量与最终组合验收。

P0 验收通过后可按上述限定范围发布；Paged KV/增量存储是提高容量效率的重要 P1 能力，不是把当前可靠性工作无限拖延的理由。真正的目标是可解释的复用收益与持续稳定运行。

## 七、当前不进入前置条件的能力

- MTP 性能与 MTP 状态缓存：继续后置；改动触及已有显式 MTP 时维护必要正确性回归。
- 非前缀任意片段拼接、CacheBlend 式 RAG 合并：前文与 GDN/PLE 历史依赖不允许直接套用，须单独算法/数值研究。
- KV 有损量化、跨量化恢复：不能混入当前精确缓存合同。无损压缩也需先证明 CPU 成本、暂存空间与 I/O 收益。
- RDMA、CUDA IPC、GDS、跨机器缓存控制面、通用多模型后端：待本机状态协议和 PD 服务成熟后按实际部署需求扩展。
- 通过迁入 Core ML/ANE 解决缓存管理：硬件后端探索不替代身份、所有权、容量和 I/O 管理，当前保持 MLX 计算路径。
