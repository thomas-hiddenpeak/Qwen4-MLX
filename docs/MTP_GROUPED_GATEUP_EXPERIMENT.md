# S3 专家共享 gate/up 读取的局部筛选

2026-09-07。288 项有限值及逐位比较全部通过，但新实现没有通过性能筛选。六组中五组慢于当前逐 token S1 路径，一组基本持平；不接入生成模式，不改变默认。实际专家重叠的机会见 [路由采集结果](MTP_EXPERT_OVERLAP.md)，本页记录第一个算子实现的结果。

## 实现与输入边界

GPU 上先建立一个 `[30,3]` INT32 成员表，以首次出现的专家选择为 owner，其余非 owner 单元均为 -1。gate/up 中每个 owner 的一份 packed Q4/scale/bias 读取供一至三个 token 使用，各 token 保持独立累加器并写回原 `[token,slot,640]`。没有成员的线程组在读权重前一致退出，不含某 token 的 owner 不计算该 token。计划、激活、down 构成普通惰性图依赖，不需要 CPU 路由读回或权重副本。

原 gate/up 和 down Metal 源码逐字保留，原 down 沿用 token-axis 索引。新 gate/up 保持原八个 affine 表达式、lane 内 K 顺序、SIMD 归约、BF16 舍入、sigmoid LUT 及槽位归约。单成员仍可能承担最多 24 个源码级 FP32 累加器的资源成本；源码条件分支不能证明编译后的寄存器占用下降。

显式 `probe-gpu-moe-grouped-gateup` 加载第 0、45 层的原始权重，每层 14 张 MoE 张量、1,428,034,560 源字节，分别驻留完成该层三个案例。六组 IDs 从实际路由采集按预定条件取首个符合记录，包含 U30 不重叠、低重叠、仅两行共享及三行共享，保留原槽位。文件只有专家 IDs，没有原激活或路由分数。

探针使用三行不同的确定性合成 BF16 输入，正常执行 router，并保留它按槽位产生的分数，再用冻结 IDs 选择专家。这个分数与强制选择的 ID 不对应；测试对象是可核对的完整 MoE 算子，包括 router、routed、shared 和合并，不能称为实际模型轨迹重放。六组覆盖模式和极端情况，不按真实出现频率加权。

## 正确性与计时

三路均使用同份输入、分数和原始权重：A 为当前逐 token S1 路径，B 为已有 token-axis，C 为成员规划加共享 gate/up，再调用原 token-axis down。

每组先做 45 项逐位/有限值比较，包括激活、每槽专家输出、路由结果、共享分支、最终输出、原 router IDs、CPU 成员表 oracle，以及诊断/普通路径一致性；计时后再检查实际最后一次 A/B/C 输出，共 6×48=288 项。全部通过。

每组每路 3 次预热、12 次测量，六种 A/B/C 排列各执行两遍；共 54 次预热、216 次计时完整保留。样本包含新图构建和同步求值，C 包含规划成本，读回在计时外。下表为完整样本中位数，A/C 或 B/C 大于 1 才表示候选较快。

| 0 / 24 | 0.4012920 | 0.4250835 | 0.4123535 | 0.973175 | 1.030872 |

U15 相对 B 的 6.70% 改善仍没有胜过 A；其两个六轮区块 A/C 为 1.039114 / 0.980495，B/C 为 1.106076 / 1.039338。没有案例建立同时胜过 A、B 约 5% 且可重复的收益。不删除后半数据，也不把六组平均成整模型加速值。

记录中的 C 图构建中位数约 22–25 μs，低于 A 的 30–34 μs；但 C 同步求值等待约 353–433 μs，均高于 A 的 337–399 μs。更少的 Swift 图节点没有降低总耗时。这里的等待包含调度、GPU 执行和同步，未采集纯 GPU span，不能据此确认寄存器压力、缓存复用或某个子 kernel 是原因。

## 复现与决策

先由既有控制器核对并交接模型所有者，再运行：

```sh
.build/release/ane-runner probe-gpu-moe-grouped-gateup \
  --model-dir ../qwen38-ssd/models/Qwen3.8-Flash-Next-MLX-SSD-Stream \
  --route-cases fixtures/gpu-mtp-route-overlap/route-cases.json \
  --output NEW_REPORT.json
```

公开 fixture 与实测文件逐字一致，SHA `a72f94be9312b8ec5f16f2b8e2e911a2889a90a57061070ddf9f3b38e850d214`。保留的来源路径仅说明本机采集位置，不要求复现者拥有原始大报告。

初次 release 构建 53.10 秒通过；去掉新 shader 三处空白行尾空格后，最终 release/测试构建 60.13 秒及 13 项选定 CPU 检查通过。GPU 实测二进制 SHA `3c9309fb66966c2a120504e0f4b4aac384bc2ff01740ea6b348c02a1a6690d33`。原始结果 `results/mtp-expert-overlap-v1/operator/probe.json`，SHA `847cb3b9207d21a1d764e7df6df52b8b7e20c75a99977e95c8113fb0c383c399`；同目录保存 plan、ledger 和 postflight。145 个文件 SHA、102 个模型 payload 大小/mtime 复核通过，参考 PID 51729 按原参数恢复并核对监听、空闲和 MTP/drafter 关闭。

`passed` 字段只表示数值和样本完整，不代表性能通过。保留显式算子探针便于后续比较，生成入口没有选择该 kernel 的策略。后续若尝试按一个、两个、三个成员分别编译的 kernel，必须把新增 dispatch 成本纳入，并继续保留低重叠对照；这只是待验证假设，本次尚未实现。

独立复算 `operator/independent-audit.json` 核对了全部比较、计时边界、排列平衡、中位数及两个六轮区块，同时重建原始路由来源和合成输入的 LCG/三行 SHA，结果一致。构图与等待的中位数分别计算，不能直接相加充当总中位数。

探针接入将 `GPUMoE.forward` 原参数逐项透传到私有实现；只有显式 probe 传入强制路由及 grouped 选择。随后用同一二进制回归现有 AR 与 D2 各一次原 11k/128 请求，完整 IDs、length、offset11184、12 个 QSA 层通过，路由采集关闭；D2 的接受直方图和计数与改动前一致。此次 prefill target 为 514.895 / 515.298 token/s，decode 为 32.170 / 37.043 token/s，只作普通路径的行为回归，不是候选整模型测试或新发布收益证据。记录在 `results/mtp-expert-overlap-v1/regression/`；146 个文件 SHA 及 102 个 payload stat 复核释放，最新恢复参考 PID 52066，精确参数、监听、空闲及 MTP/drafter 关闭已核对。
