# 验证阶段 S3 QKV 的 TM2 筛选

2026-09-07。真实四层BF16 QKV权重的42项逐位/有限值比较通过，TM4→TM2没有建立可重复加速，不扩大到整模型，不修改默认。仅保留显式算子实验入口。

[验证热点诊断](MTP_VERIFY_HOTSPOTS.md)将包含投影、前后处理和capture的GDN块排在第二位，占选中GPU跨度约25%。这提供局部筛选方向，未单独证明QKV占比或寄存器瓶颈。

## 改动及数值边界

`GPUVerificationLinear(experiment: .qkvS3TM2)` 仅在S3、K2560、N10240、BN1时将TM4改为TM2，BM8/SN32/TN4保留。Metal源码逐字不变；每个输出的lane内K累加顺序、shuffle归约及最终BF16舍入保留。源码中的每线程累加器从12个float减为6个，threadgroup从320增至640，但未测量编译后的寄存器分配或occupancy。

实例策略不可变，默认 `.reference`，其他形状和S2/S4/S5使用原参数。没有权重副本或重排，也没有新增生成模式。两个既有CLI辅助类型仅从private改为模块内可见，以复用原输入生成公式和逐位比较。

```sh
.build/release/ane-runner probe-gpu-verification-qkv \
  --model-dir ../qwen38-ssd/models/Qwen3.8-Flash-Next-MLX-SSD-Stream \
  --output NEW_REPORT.json
```

先通过既有实验控制器交接模型所有者。探针只加载层0/4/8/12的四张 `[10240,2560]` BF16 QKV权重，共209,715,200源字节，均保持驻留。输入是既有matvec确定性公式生成的有限BF16值，三行连续生成，S2取前两行；它不是实际模型激活或完整生成轨迹。

## 固定测试结果

每层每种长度均以独立逐行S1 matmul为oracle，比较初始A/B和最后一次计时输出；S3后返回S2另检缓存复用，共42项通过。每层每种长度3对预热、12对测量，轮换层顺序并交错AB/BA；48次预热和192次计时全部保留。计时包含新图构建及输出求值，不含加载和诊断读回，也不是纯GPU时间。

| 层 | S3基线中位 ms | S3候选中位 ms | S3基线/候选 | S2未改参数对照倍率 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 0.2614375 | 0.2729790 | 0.957720 | 0.924650 |
| 4 | 0.2766875 | 0.2740000 | 1.009808 | 0.954498 |
| 8 | 0.2497705 | 0.2780210 | 0.898387 | 0.962603 |
| 12 | 0.2888960 | 0.2853955 | 1.012265 | 0.941802 |

大于1表示候选较快。S3只有两层中位倍率略高于1，没有达到约5%且跨四层稳定的继续条件。其BA顺序倍率分别为0.891858、0.937524、0.855251、0.966932；全部样本与六个不重叠ABBA区块均保留，没有删早期数据或重跑挑选。

S2双方参数完全相同，仍出现方向性差异。因此当前证据是“没有可重复加速”，不能断言S3全部回退由TM2造成，也不能用S2比值对S3事后校正出收益。
